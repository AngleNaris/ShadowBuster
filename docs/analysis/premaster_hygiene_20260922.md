# 母带前卫生滤波与声场读数口径（2026-09-22）

用户报告（《先认输再入场6 - good.mp3》）两点：

1. 低于 40 Hz 的极低频被抬升，混音惯例上这两端（含 >20 kHz）应该被削弱；
2. 处理后报告里的声场反而收窄（低频 −23% / 中频 −15% / 高频 −14%）。

追下去每一点都有两个来源：**真实 DSP 行为**与**测量/读数口径**。两边都改了，
不能只改一边——只改 DSP 的话，报告仍会用一把坏尺子告诉用户问题依旧。

## 行为与接口

### 1. 报告测量：旧报告里的 sub-40 曲线是假的

旧报告的 `compare` 用 4096 点谱（44.1 kHz ≈ 10.8 Hz/bin，48 kHz ≈ 11.7 Hz/bin）。
最窄的 1/3 倍频带只有 5.8 Hz 宽，**一个 bin 都落不进去**就被记成 −90 dB 地板：

| 频点 | 4096 点（旧口径） | 65536 点（新口径） |
| --- | --- | --- |
| 48 kHz 输入的 40 Hz 带 | **−90.00**（无 bin） | −17.17 |
| 44.1 kHz 成品的 25 Hz 带 | **−90.00**（无 bin） | −44.57 |

旧报告因此画出「40 Hz：输入 −90.00 → 输出 −16.79」（看着像 +73 dB 抬升）与
「25 Hz：输入 −30.84 → 输出 −90.00」（看着像 −59 dB 深谷）——**全都是尺子的错**，
用 65536 点复算输入，两点都能逐位复现旧值，证明差别只在 FFT 长度。

改法：`audio_metrics.COMPARE_FFT_SIZE = 65536`，`_mean_spectrum` 接受 `size` 参数
（其它调用点仍用 4096，不改既有噪声/频带口径）。白噪声校验 65536 点与解析值
差 ≤0.1 dB，且 44.1k/48k 结果一致。

**旧报告的 `compare` 数字与新报告不可直接比较**：量纲不同（旧的是空 bin 地板）。
本文档之后引用的所有数字都是新口径。

### 2. 母带前卫生滤波（`apollo_scripts/premaster_hygiene.py`）

新增独立阶段，位置在**任何母带引擎之前**（Soren 风格母带与无风格/参考独立母带
共用），因此两条链路拿到同一条处理：

- 低切：2 阶巴特沃斯高通 + `sosfiltfilt`（零相位）。零相位会把幅度响应平方，
  设计转角取 `0.8014 × 请求值`，使 `--low-cut-hz` 就是**实际 −3 dB 点**。
  实测 44.1 kHz、请求 40 Hz：20 Hz −17.62、25 Hz −11.37、31.5 Hz −6.33、
  40 Hz −3.00、50 Hz −1.36、63 Hz −0.56、100 Hz −0.09 dB（贝斯基频几乎不动）。
- 低通：1025 抽头线性相位 FIR（Kaiser β 8.6）。实测：16 kHz 0.00、19 kHz 0.00、
  20 kHz −6.02、21 kHz −108.8、22 kHz −120.8 dB。线性相位群延迟恰为
  `(taps−1)/2`，用反射填充做 `valid` 卷积补偿，输出与输入**逐样本对齐**（不做时移）。
- 报告 `stages.hygiene` 记录请求值、实际施加方式（含零相位平方）与探针响应；
  响应按实际施加方式算，不留「名义值好看、实际砍掉一半」的缝。
- 默认 `DEFAULTS["hygiene_low_cut_hz"]=40.0` / `hygiene_lowpass_hz=20000.0`，
  显式传 0 可分别关闭（两路都 0 时整阶段跳过）。母带旁路时不进入本阶段，
  保持全链路旁路的逐字节透传语义。
- 上游 delta 仍按 `vocal_out` 计算：它表达用户链路意图，本阶段是固定产品级滤波，
  不计入 delta。

### 3. 人声平衡 delta 改立体声（`apollo_scripts/vocal_adjust.py`）

平衡增益原先只灌 Mid（`_mid(v)·(g−1)` 广播到两声道），Side 被稀释；母带链再按
比例展宽后，听感就是「处理完声场反而收窄」。现改为 `v·(g−1)` **立体声注入**：

- Mid 逐样本与旧实现完全相同（`mid(v·g) = mid(v)·g`），平衡目标、活动门限、
  误差统计口径不变；
- Side 按同一增益跟随人声自身的侧向能量——这正是旧中置注入缺的那部分。
- 报告删掉 `side_delta_max_error`：旧实现断言「侧向不变」，新实现侧向按设计变化，
  该断言不再成立；`reconstruction_max_error`（`out == estimated_v + estimated_a`）
  保留，仍精确成立。`tests/test_vocal_mid_prominence.py` 对多组增益断言
  `out == mix + v·(g−1)`、Mid 增量等于旧中置注入值、Side 增量等于人声自身侧向
  能量按同一增益（atol 1e-12），gain=0 时逐样本不变。

### 4. 母带 widen 频段预算放宽（`mastering/soundstage.py`）

旧预算（`120–2k: 0.30/+1.5 dB`、`2k–8k: 0.45/+3`、`8k–Nyq: 0.45/+3`）在真实作品上
由 120 Hz–2 kHz 那条独占，8 dB 请求只兑现 **0.2288（+1.79 dB 侧向）≈ 14%**，
用户听到的是「旋钮没反应」。现按单声道兼容层级给阶梯：

| 频段 | 旧 fraction / 增长 | 新 fraction / 增长 |
| --- | --- | --- |
| 120 Hz–2 kHz | 0.30 / +1.5 dB | **0.40 / +3 dB**（S/M ≤ −1.76 dB） |
| 2–8 kHz | 0.45 / +3 dB | **0.50 / +4 dB**（S/M ≤ 0 dB） |
| 8 kHz–Nyq | 0.45 / +3 dB | **0.50 / +4 dB**（S/M ≤ 0 dB） |

全局仍保证 Side 能量不超过 Mid（S/M ≤ 0 dB），`b < a − 0.05 dB` 的「本该加宽却
变窄」保护不变。实测同一首歌：兑现 0.2288 → **0.4914（+3.47 dB 侧向）**，
仍由 120 Hz–2 kHz 那条封顶（0.4914），中高频两条封顶 0.5849。

### 5. 报告页声场读数改 dB（`audio_metrics._band_widths` + `ui/app.js`）

宽度比 `sideE/(midE+sideE)` 是非线性压缩：0.03 → 0.02 只有 **−1.4 dB**，写成
「−23%」会把轻微收窄读成大幅收窄，mid 加厚时尤其误导。改成：

- 后端 `band_widths[key]` 同时记录 `width` 与 `side_mid_db = 10·log10(sideE/midE)`；
- 报告页扇形底部读数改为**该频段 S/M 电平变化 dB**，±0.5 dB 内读作持平（灰）；
- 标题行的前后宽度比与钻石几何不变；
- 旧成品报告没有 `side_mid_db` 字段时由宽度比反推（`10·log10(w/(1−w))`），
  连 `width` 都没有才退回百分比——两种旧成品都能读，口径统一。

### 缓存与 GUI

- 新参数进入既有阶段缓存参数；DSP 源码哈希变化自动失效旧缓存，无需手动清理。
- **GUI 暂无卫生滤波开关**（与其它隐藏参数一致走默认值）；命令行
  `processing_cli.py --hygiene-low-cut-hz / --hygiene-lowpass-hz` 可显式传值，
  传 0 关闭。是否需要界面开关留待用户决定。

### 已知限制

- 旧报告的 `compare`（4096 点）与新报告（65536 点）不可直接比较；跨版本看曲线
  必须用同一份测量代码重算。
- 卫生滤波是固定产品级滤波，不外露为音色旋钮；若用户希望 <40 Hz 有内容保留
  （如 808 sub），需要 GUI 开关，当前需走命令行。
- 本次验收为测量 + 浏览器渲染验证，**未做听感盲听**；40 Hz/−3 dB 与 20 kHz/−6 dB
  的取值来自混音惯例，若用户听感上认为砍多/砍少，这两个默认值在 `DEFAULTS` 里单点可调。
