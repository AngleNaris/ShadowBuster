> 那版换名时旧名淡出、新名淡入，视觉上更像「换了一张牌子」而不是「带子滚过去」。

## 起因

用户的原话：

> 现在滚动文件的时候，文件名感觉是淡入淡出+位移动画，我希望能做的像是真的从上面或者
> 下面滚动到窗口里的效果。

上一版 `setPlayerFileName` 用两个 `animate()` 关键帧做透明度 0→1 的交接（旧名淡出、
新名淡入，各带少量 `translateY`），读起来是「渐变换字」，不是「滚轮/纸带转过去」。
用户要的是后者的物理感：名字贴成一条带子，被框沿裁掉，整条平移一行高。

## 行为与接口

### 结构（`ui/index.html` / `ui/style.css`）

- 动画期间临时往按钮里塞一个 `.mq-roll` 带子：绝对定位盖住名字区
  （`top:0; bottom:0; left/right: calc(var(--pf-tick-w) + var(--s-1))`），
  里面两行 `.mq-roll > span`，各占「一个框高」，一上一下就是旧名与新名。
- **裁切交给按钮本身**（`.player-file-picker { overflow: hidden }`），带子自己不裁。
  这是本轮踩过的坑：元素自身的 `overflow:hidden` 裁窗会跟着 `transform` 一起走，
  给带子加 `overflow:hidden` 后，整块（含裁窗）滑出框外，框里中途是空的。
  裁在按钮上，带子从框沿下面滑过去，才是「滚过窗口」。
- 带子滚的是 `translateY(0%) → translateY(-100%)`（或反向），100% = 带子自身高度
  = 按钮内高（44px 控件 − 2×1px 边框 = 42px），正好一行，落点无残影。
- 刻度带 `.pf-ticks` 结构不变（`--pf-tick-w: 9px`，1px 刻度 / 10px 周期）。

### 时序与方向（`ui/app.js`）

- 方向：`rollDir > 0`（滚轮向下 = 下一首）→ 带子 `[旧, 新]`，`0% → -100%`，
  新名从下面滚进来；`rollDir < 0`（上一首）→ 先 `roll.prepend(roll.lastElementChild)`
  换成 `[新, 旧]`，再 `-100% → 0%`，新名从上面滚进来。
- 时长 260ms、`cubic-bezier(.22,.61,.36,1)`——与 `rollTicks()` 同参，名字与刻度一起停。
  早先试过 `.3,.7,.3,1` 太前倾（前 1/4 时间走完 ~60% 行程），换回现在这条更匀速。
- 落点清理：`anim.finished`（成功/取消都走 `land`）里删带子、恢复
  `#player-file-name > .mq`（动画期间 `visibility: hidden`）、清 pending；
  悬停态（`dataset.hovering`）则重挂跑马灯。
- 连滚：`nameRollPending` 记「当前动画的目标名」，新一次滚动的旧名取
  `nameRollPending ?? inner.textContent`；`nameRollToken` 只让最后一段动画落地写文本，
  中间被顶掉的段落不写，避免闪回。
- 无障碍/降级：`prefers-reduced-motion: reduce` 或没有 `rollDir` 时直接改文本，不做动画。

### 接口面

无后端/接口变化；纯前端（`ui/` 三个权威文件 + 测试断言 + 缓存版本号）。
