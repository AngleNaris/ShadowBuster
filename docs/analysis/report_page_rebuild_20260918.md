## 起因

用户反馈「处理之后的声场反而变窄了」，要求确认是处理有问题还是报告渲染有问题。
结论是报告口径有问题：旧版整曲宽度 `sideE/(midE+sideE)` 被低频能量主导，而低频
本就被有意收紧以保单声道兼容性，于是整曲读数显示变窄，掩盖了高频实际变宽
（实测 0.11 → 0.13，+19%）。按频段呈现后矛盾消失，因此连同整页一起按设计图重做。

## 行为与接口

- `audio_metrics._band_widths` 新增 `measure_audio()["band_widths"]`，键为
  `low 20–250`、`mid 250–4000`、`high 4000–20000`、`wide_gt250 250–20000`，
  每键 `width = sideE/(midE+sideE)`（双声道以外返回 `None`）。
- `write_quality_report` 新增 `meta`：`generated_at` 与 `input_format` /
  `output_format`。`measure_audio` 只拿到样本数组，取不到 subtype，故格式位深
  另用 `sf.info` 读容器；`FLOAT`/`DOUBLE` 无位写下按 32/64 补齐。
- 报告页六块：`rp-head`（版本徽标 + 文件名 + 格式芯片 + 分析时间/处理链）、
  `rp-summary`（4 项 KPI）、频率响应对比（1/3 倍频程曲线 + 共享 X 轴的 Δ 条）、
  响度与动态（5 行哑铃，固定物理量纲刻度）、立体声场（3 频段俯视扇形）、
  频谱变化（原始 / 处理后 / 变化(Δ) 三视图 + 发散色标）。
- 配色语义固定为：处理前 `--c-text-dim`、处理后 `--c-accent-hi`、Δ 提升 `--c-ok`、
  Δ 削减 `--c-support`。`--c-ok` 与 `--c-support` 不随 accent 主题变化，所以发散
  色标在 5 种主题下语义稳定；一律经 `cssVar()` 读取，`DELTA_LUT` 每次
  `renderReport()` 按当前主题重建。
- 质感沿用应用规范：无圆角、拉丝金属面板、`--inset-well` / `--inset-deep` 凹槽；
  数值走 `--mono` 与 `tabular-nums`，负号统一 U+2212 而非连字符。

## 验证中发现并修掉的判读缺陷

1. 缩放视野外的频点被钳到画布左右边缘，画出两条假垂直线，整张图看起来像渲染
   崩溃；改为跳过越界点并抬笔，折线只覆盖真正可见的频段。
2. 最小缩放跨度 1.05 允许窄到只剩一个 1/3 倍频程中心，提到 2.5（≈4 个中心）。
   当时另补了「视野 452 Hz–2.8 kHz · 双击复位」徽标——该徽标在复查第 8 项被要求
   撤除（见下文），缩放态改由曲线本身表达。
3. 扇形只画 ±45° 外框，而真实声场半张角只有 10~25°，窄扇看着像空图。补 15°/30°
   导引辐条（左侧标度数）与处理后实测半张角标注（扇内标度数）。
4. 哑铃行前后圆点贴近时两个上标数字叠成一团；小于 11% 轨宽时合并为居中
   「前 → 后」，右侧数值列仍各占一格，不丢信息。
5. Δ 频谱的行归约原用 `max|Δ|`，会把单 bin 泄漏与限制器抖动放大成主信号；改为
   频率区间内均值。色标线性映射到 ±12 dB 满量程时，实测 ±1~3 dB 的变化整张图
   压成黑色，改用 0.55 指数伽马抬升低幅值，单调性与色标刻度仍一致。
6. 扇形说明文案写死「中频宽度扩展」这类结论，与同屏实测 −11% 自相矛盾；改为
   中性描述 + 实测带符号百分比。
7. `pair.inM` 缺失时 `rpNum(null)` 返回 0，读数会显示 0.00 而不是「—」；显式判空。
8. figcaption 内联图例在窄面板下中文断字（渲染成「Δ 提 升」）；改为整项不折行、

### 第 4 项：前提不成立，但口径确实要改

旧 KPI 用的是 `wide_gt250`（250 Hz–20 kHz），低频本就被排除，所以「永远都是减少」
不是低频造成的。真正的问题是能量加权：该区间能量几乎全在中频，于是中频 −11% 把
高频 +19% 吃掉，整曲只剩 +0.3%。改为中频、高频各自换算 S/M 比（dB）后等权平均，
读数 +0.16 dB，符号与两个分频段实测（−11% / +19%）不再互相打脸；分布本身交给
三张钻石图承载，KPI 不再试图用一个数概括声场。

### 第 12 项：扇形 → 钻石

初版扇形按 `UP/DN` 参数化，L/R 角点深度取 `1/tan(域角)`，15° 一档时 DN≈3.7，钻石
被拉成上窄下长的细 kite，顶角「中」字被画布上沿裁掉，实测角度标注又压在顶角上
叠字。改为顶角（中）到底角（听者）定高、L/R 恒落在半高处的标准钻石形，域角只决定
半宽、窄画布内按可用宽度回缩（`slope = 2·halfW/boxH` 保证角度关系自洽）。角度尺度
与实测半张角移到图内底行（左「角度域 ±15°」、右「实测 11°」），变化百分比居中，
图下不再有任何 DOM 文本行；前后宽度读数并入频段标题行右侧。

### 第 13 项：马赛克根因在后端下发数据

`_spectrogram_payload` 原先下发线性 rfft bin，前端显示时按对数频率重排：100 Hz 以下
一个 bin 要铺几十行，画面糊成马赛克。改为后端直接下发对数行——行中心自 30 Hz 几何
级数排到 Nyquist，每行取所属分数 bin 区间内的**带最大值**；只有区间窄于一个 bin 的
最低几行退化为线性 dB 插值。前端按行 1:1 使用（`specSpans`），旧报告（无 `fmin`）
仍走对数重排分支。60 s 样本实测：512 行 × 1290 列，编码 0.12 s / 860 KB。

## 第三轮：配色自动推导 + 版式六项（同日）

### 配色不再逐主题凑色

原先 Δ 语义色直接读 `--c-ok` / `--c-support`：这两个变量不随 accent 变化，五种主题
下都是同一组绿/蓝，等于「图表配色与主题无关」。改为由主题色推导五槽：

| 槽位 | 推导 | 用途 |
|------|------|------|
| 主题色 | `--c-accent-hi` | 处理后（主序列） |
| 弱化主题色 | 主题色向中性色混 42% | Δ 衰减、主序列的次要填充 |
| 中性色 | `--c-text-dim` | 处理前 / 轴 / 网格 / 文字 |
| 对比色 | 主题色色相 +180°（HSL 往返，保饱和度与明度） | Δ 提升 |
| 弱化对比色 | 对比色向中性色混 42% | 导引、次要标注 |

`rpThemeColors()` 是唯一的取色入口，`DELTA_LUT` 每次 `renderReport()` 重建，换 accent
或切浅色模式都自动跟。弱化一律「向中性色靠」而不是「向底色靠」——向近黑的底色混会让
弱化色在深色模式直接看不见。

踩坑：第一版把 Δ 两极做成「对比色 / 弱化对比色」，同色相只差饱和，Δ 频谱整张糊成
一片绿、分不出正负。发散两极必须落在两个色相上，故改为「对比色（提升）/ 弱化主题色
（衰减）」。

### 版式与文案六项

1. **Δ 子图铺满高度**：固定 `h*0.22` 时频响卡片下半截全是空白，改为与主图分剩余高度
   （`(h - padT - padB - gap) * 0.34`，下限 56px）。
2. **主图按可见数据占满 + 缩放过渡**：压缩窄带只在可见最低点真的低于 `KNEE − 6 dB`
   时才保留，且窄带高度按 `[压缩段 dB, 主段 dB]` 比例分配（封顶 34%）——缩放到看不到
   低频滚降时曲线不再被一段近乎空白的窄带顶上去。视野变化走 190ms 三次缓出补间，
   拖拽平移传 `instant` 保持跟手。顺带修掉一个真 bug：缩放锚点原先按固定 20–20000 Hz
   反解，缩放后锚点算错、视野会单向漂移。
3. **动态行侧向偏移**：每行补一个物理参照区间（LUFS −24..−2、dBTP −6..0、LU 0..20、
   Crest 4..20、相关 −1..1），按取值在其中的相对位置整体横移窗口。窗口宽度不变，
   变化幅度照样好读，但五行不再都停在正中；贴边的读数补了 `rn-start/rn-end` 对齐。
4. **钻石图占满宽度**：半宽原先 `tan(域角)×高度/2`，15° 一档只有约 28px，等于看不清。
   改为域角张满可用宽度，θ 以 `q = tanθ/tan(域角)` 落在上棱参数位置上；撑满后画布被
   卡片拉高会退化成一根针，故再按半宽限高（≤3×半宽）并垂直居中。
5. **频谱卡与声场卡等高**：`.rp-fig` 改纵向 flex，标题行固定、图区 `flex:1` 吃剩余高度，
   声场三格与频谱画布最小高度一致（150px）。实测两卡均 408px。「只反映频谱平衡」那句
   说明按用户要求撤下，说明文案之后统一补。
   随后追加要求：**第二排必须限高**。408px 不是 flex 没夹紧，而是 `height: auto` 的
   canvas 会按自身属性推出的固有宽高比定高——JS 每次绘制都把属性写成实测尺寸，
   频谱画布因此锁在约 340px 并把整排顶开，钻石图跟着被拉成针。改为画布以
   `flex-basis: 0` 参与分配，并给两张卡 `max-height: 320px`；把内容区强行撑到 1400px
   高实测：两卡仍为 320 = 320，钻石画布 223px、频谱画布 260px，形状不再走样。
6. **KPI 名副其实**：`低频清理 / 20–250 Hz 能量` 名实不符（读数就是该频段能量变化，
   与「清理」无关），改为 `低频能量 / 20–250 Hz 变化`；`人声空气感` 同理——该频段是
   全曲 3–8 kHz，并非人声单独测量，改为 `空气感能量 / 3–8 kHz 变化`。

## 第四轮：纵轴分段、Δ 合并、固定量程与层级（同日）

四项要求：① 频响曲线仍太平缓，要把远超出均值范围的部分大幅压掉（每格 dB 跨度不再相等）；
② 差异不再单独成图，直接在实际曲线上给提升/衰减上色；③ 响度各行给一个常用总量程，
不再随本行取值改变整条轨道的尺度（除非取值超出默认量程）；④ 卡片小标题用灰、只有主标题
用白，顶部四大 KPI 数字用主题色。

### ① 纵轴按百分位分段，格高不再等 dB

原先固定 `KNEE_DB = −30` 一条折线：母带整体偏轻时（本例曲线落在 −9…−35）折点几乎不起
作用，中频一小段起伏仍被摊在整幅高度里。改为按**当前可见样本的分位数**取核心带：

- 核心带 `[coreLo, coreHi] = [at(0.04), at(0.96)]`，再按跨度的 8%（2…6 dB）留边；
  跨度不足 6 dB 时以中点撑开，避免纯音素材把核心带压成零高度。
- 核心带以外的两段尾巴按 `TAIL = 8` 倍压缩，像素高度由
  `coreH = plotH / (1 + (upTail + dnTail) / (coreSpan * TAIL))` 反解，上下尾巴再按各自
  dB 跨度分配。于是「一格 = 5 dB」的核心区与「一格 = 13 dB」的尾巴同屏共存。
- 折点画一条更亮的分隔线并在右端标 `1:8`，读图的人知道刻度在此改变密度；尾巴不足
  14px 高时不画刻度（`room = floor(px / (16*dpr))` 反推档距），避免叠字。

### ② Δ 并入主曲线

删掉「差异 Δ (dB)」整条子图（连同 `Yd`/`stripMid`/`stripH`），主图吃满卡片高度。前后两条
曲线之间的区域按符号填色：单段取两端差值均值 `≥ 0` 判提升（对比色）否则衰减（弱化主题色），
`globalAlpha = 0.34`，先铺填充再描线，故两条线本身不受影响。

代价要讲清楚：**Δ 的绝对 dB 刻度没有了**，提升多少只能看色带宽度对左侧刻度的相对位置。
换来的是「在哪一段被抬、抬了还是削了」一眼定位，不必在两图之间对横轴。

### ③ 响度与动态：每行固定常用量程

`RP_DYN` 每行补 `ref` 字段（LUFS −20..−6、dBTP −6..0、LU 0..12、Crest 6..18、相关 −1..1），
轨道尺度默认取 `ref`，只有前后取值超出时才外扩 4% 边距。上一轮「按本行取值 ±50% 定标」
被推翻：那样每行的 0 点与满尺都不一样，五行并排读不出「这一行偏大还是偏小」，而固定量程
+ 侧向偏移正好把这个信息还回来。刻度与圆点同值同位时只画刻度（`dup` 判重按数值比较，
原先比字符串会把 `−0.40` 与 `−0.4` 当成两个）。

### ④ 层级与主题色

`.rp-cap-zh` 保持 `--c-text`（卡片主标题），`.rp-kpi-label / .rp-dyn-label b / .rp-fan-hd b`
降到 `--c-text-dim`，`.rp-kpi-sub` 用 `--c-text-faint`；`.rp-kpi-num` 取 `--c-accent-hi`。

### 验证中发现并修掉的三处

1. **KPI 箭头是最后一处写死色**：`.rp-kpi.up/.down` 仍用 `--c-ok` / `--c-support`，五种
   accent 下永远是同一组绿/蓝，等于在推导配色里夹了第三个来源。改为 `--rp-boost` /
   `--rp-cut`，由 `rpThemeColors()` 把推导结果回写到 documentElement 的 CSS 变量（只在
   值变化时重写），DOM 与画布从此同源。
2. **切主题不重绘**：报告所有颜色取自 CSS 变量派生，但切换 `data-accent` / `data-mode`
   后画布仍是旧主题色，直到切走再回来或 resize。补 `document.addEventListener("sb-theme")`
   在报告页可见时重绘。实测：切到 moss 画布哈希变化、切回 indigo 哈希精确复原。
3. **浅色模式下对比色浮在白底上**：色相旋转沿用主题色明度，indigo 的对比色 `#cfae52`
   在 `#fafafa` 面板上只有 2.1:1，Δ 上色几乎看不见。补 `ensureSep()`：按 WCAG 对比度
   以**面板色**（不是页面底色）为参照，把推导色向文字色回推到 2.6:1 为止，色相不动。
   十种组合（5 accent × 2 mode）实测 boost/cut 全部落在 2.62…7.44。

### 第四轮验证

- 真实浏览器逐主题核对：默认 ember 深色下 40–150 Hz 的提升带清晰可见；浅色 indigo 下
  箭头与色带回写后可读；五 accent × 两 mode 的推导色对比度成表核对。
- 缩放往返：6 档放大后 10 档缩回，画布像素哈希精确等于「切走再切回」的新鲜全量程渲染，
  且双击复位得到同一哈希。
- 卡片高度：频响与响度动态同排等高，立体声场与频谱变化仍为 320 = 320。
- 缓存版本递增为 `style.css?v=68` / `app.js?v=64`。

## 第五轮：三色语义统一、曲线实线、钻石正方形（同日）

三项要求：① 颜色语义全站统一——提升=对比色、原始=中性色、降低/衰减=主题色，图元与数字都算；
② 频响曲线不要虚线，一律实线，且处理后「提升的曲线段落」本身要用对比色描出来；
③ 声场与频谱变化两卡继续限高，声场图至少正方形。

### ① 三个语义色，图元与数字同源

`rpThemeColors()` 收敛为四个字段：`before`（中性）、`after`（主题）、`boost`（对比）、
`cut`（主题，与 after 同值——成品偏低就是衰减，本来就是同一件事）。原先的
`themeSoft / contrastSoft / theme / neutral / contrast` 没有任何调用点，删；
`versionColor()` 那张写死的五色轮（`#3d6fb4 / #3fbf7f / #b07a2e / #8a5ce5`）也删——
它正是「逐个凑色」的最后一处。

落到每个面板：

| 位置 | 原始/处理前 | 提升/变宽 | 衰减/变窄 |
| --- | --- | --- | --- |
| KPI 卡（图标+数字+箭头） | — | `--rp-boost` | `--rp-cut`（持平=中性灰） |
| 频响曲线与色带 | 中性 | 对比 | 主题 |
| 哑铃行（圆点/连线/读数） | 中性 | 对比 | 主题 |
| 钻石图（图形+实测+百分比） | 中性 | 对比 | 主题 |
| Δ 频谱与色标 | — | 对比 | 主题 |

哑铃行的方向由 `renderDynamics` 写进行 class（`up/down/flat`），CSS 再把处理后一侧整体染色；
阈值取半个末位读数（`halfLsb`）——差值小于它时两个数字印出来一模一样，就不该让颜色替它表态。
圆点的填充与光晕统一走 `currentColor`，避免点是一色、halo 是另一色。

### ② 实线 + 提升段描对比色

原始曲线去掉 `setLineDash([5,4])`，两条都画实线，靠颜色区分（中性 vs 主题）。折线改为
逐段描边：先整条按 `after` 画一遍，再把「两端相对原始差值均值 > 0.2 dB」的段用 `boost`
叠第二遍，`lineCap: round` 补住分段处的折角缺口。视野外的频点仍记 `null` 跳过，不钳边。

### ③ 钻石框正方形 + 两卡继续限高

真实缺陷是**扁**：原先 `boxH = min(availH, halfW*3)`，宽窗口下一格 229px 宽而可用高只有
114px，钻石被画成 181×114（宽 ≈ 高的 1.6 倍）。改为宽度让位给高度：
`if (availH < halfW*2) halfW = availH/2`，框恒为正方形，两侧留白好过声场形状失真。
配套把 `.rp-fan canvas` 的 `min-height` 从 150 提到 180——卡片 chrome 固定 97px，
280 的帽高对应约 180 的画布，正好把可用高度用满（此前白扔 30px）。
两卡帽高 320 → 280；再低就会把正方形钻石压成一条扁菱形。

### 验证中发现并修掉的

**Δ 频谱在浅色模式下整片发粉**：衰减色由「弱化主题色」换成饱和主题色后，色标低端把
0.5dB 以内的噪声底也染上了色，近白面板上尤其明显。补 `DELTA_DEADBAND = 0.4`：先扣死区
再做原有的小指数伽马。随后用真实载荷核过分布——660480 格里 67% 落在 −0.4…−3 dB、
均值 −1.05 dB、只有 17.5% 在 ±0.4 以内，也就是说剩下的粉色是数据本身（成品逐格带内峰值
普遍降了 1~3dB），不是映射缺陷；再往下压死区就会开始骗人。

### 第五轮验证

- 真实浏览器（ember 深/浅两色）逐面板核对：KPI 图标/数字/箭头同向同色；哑铃行
  `up/flat/up/down/up` 与实测取值一致（响度 −9.3→−9.2 升、真实峰值 −0.4→−0.4 平、
  动态范围 3.1→3.2 升、峰值响度比 11.8→11.5 降、相关性 0.85→0.87 升）；

- 全量 `python -m pytest -q`：见提交前最后一次运行结果。

实测报告各块左边缘 30px，而上方待处理队列面板 18px，两者差一截。
上下仍留 `--s-3`，否则版本胶囊贴着队列按钮，看起来像队列的下一行。

### ③ 动效重做：重放数据，而不是给卡片套淡入

第七轮的 `.rp-kpi / .rp-fig` 淡入被判定为无效：它只说明「换了张图」，
读数、圆点、曲线本身仍是硬切，读不出数值怎么变的。改为一个数据重放驱动：

```
rpShown   上一次真正画到屏幕上的数值（morph 的起点）
rpPending 本次渲染算出的数值，渲染结束提交为 rpShown
rpHooks[] 各渲染器登记的重放闭包 (u, reveal) => void
rpRunAnim(mode)  reveal 620ms / morph 420ms，rpEase 三次缓出，prefers-reduced-motion 跳过
```

`renderReport(mode)` 在调用各渲染器前开一个空的 `rpPending`，渲染完把
`rpPending → rpShown` 提交，再按需 `rpRunAnim(mode)`。五个重放点：

| 对象 | reveal（进页面） | morph（换版本） |
| --- | --- | --- |
| KPI 数字 | 从 0 计数到显示值 | 从上一版读数插值 |
| 哑铃行 | 圆点与读数都从 0 走 | 圆点位置、上方读数、连线一起插值 |
| 声场钻石 | 张角从 0 展开，底部百分比同步长 | 前后两个张角一起补间，读数随之变 |
| 频响曲线 | 画布 `clip-path` 从左到右揭开 | 处理后曲线逐点插值，纵轴量程按插值结果重算 |
| 频谱位图 | 同样按左右揭开 | 先铺上一版位图，再按进度叠新版（交叉淡化） |

三处取舍：

- **钻石角度档位锁死**：`drawFieldDiamond(..., fixedDom)` 由 `renderStereoFans` 按最终取值
  算出档位再传进去。否则钻石从 0 长起来时会边长边换档（15°→25°），框线跳成「图坏了」。
- **频响纵轴跟着插值走**：量程本来就是按可见数据百分位现算的，把插值后的曲线喂进去，
  曲线与刻度一起滑到新状态，不需要额外记录旧几何。
- **静态重绘一律画终态**：缩放、换主题、resize 都不带 `anim`，`drawSpectrumChart` /
  `drawSpecBitmap` 进门先把 `clipPath` 清掉，绝不留半张被遮住的图。
  频谱三视图切换与「频谱载荷晚到」两处不属于渲染流程，用 `rpWipe(canvas, ms)` 单独走一次揭开。

### 验证中发现并修掉的

- `renderDynamics` 里 `rows.push(...)` 用了从未声明的数组 → 第一行就抛 ReferenceError，
  整条 `renderReport` 链断掉：哑铃只剩一行、声场停在上一趟的空态。浏览器实测才抓得到，
  源码字符串断言完全看不出。修法是把 `const rows = []` 补在循环前。
- 探针桩里 V2 复用 V1 的报告与频谱字节，换版本读数一模一样，morph 无从观察。
  改为给 V2 生成扰动过的报告（LUFS/LRA/true peak/crest/相关性/分频段宽度各移一段，
  `output_db` 加倾斜）与整体提亮的频谱字节，morph 才真的动。

## 第九轮：段控缺边、预览播放条瘦身与两段式点击（2026-09-19）

四项要求：① 右上角 tab 选项的左侧会被遮挡一部分；② 预览播放器移除多余的文件名；
③ 版本选择改成与报告页一致的交互，并额外给出「预览」以便切回之前渲染的预览片段；
④ 第一次点击频谱时，若点中的不是当前激活轨，只切换该轨并继续播放，第二次点击才调整进度。

### ① 高亮块少一条竖边：分隔线与描边抢同一个像素

现象是选中块（`tab-glider`）的左竖边看不见。按用户截图逐像素量：块右边缘
x=910 是 `rgb(109,85,184)`（accent-hi 描边），块左边缘 x=848 是 `rgb(53,50,63)`
（`--c-border` 灰）——左边的描边被灰线盖掉了。

根因不在滑动块，而在 `.tab-btn + .tab-btn { border-left: 1px }`：分隔线正好落在
按钮盒子的左边缘，而块的位置取自 `btn.offsetLeft`，两者是同一个像素；按钮
`z-index: 1` 在块之上，谁赢取决于 DPI 取整。所以同一份代码在 100% 缩放下右边露出
描边、左边被吃，换 DPI 又反过来。

不靠几何假设来修：让分隔线本身服从块的描边。

```css
.tab-btn[aria-pressed="true"] { border-left-color: var(--c-accent-hi); }
.tab-btn[aria-pressed="true"] + .tab-btn { border-left-color: transparent; }
```

选中项自己那条线改成同色（谁盖住谁颜色都对），它右边那枚的线让位为透明，
块的右描边露出来。未选中相邻两枚之间仍是灰色分隔线。

### ② 播放条去掉重复文件名

`.spec-name#pv-file-label` 与上方队列选中的曲目是同一个字符串，删掉元素、
`refreshPreviewFiles()` 里的赋值和 `.spec-name` 规则一并清掉。播放条只留
播放键、时钟与音源胶囊。

### ③ 音源切换与报告页统一为胶囊

原生 `<select id="pv-version">` 换成 `<div class="pv-chips" id="pv-version">`，
`renderPvVersions()` 生成 `.rp-chip` 按钮（复用报告页同一套样式与 `aria-pressed`
单选语义），标签用 `V1 / V2` 与报告一致。

关键差异是**「预览」升格为一等选项**：旧下拉里它叫「预览片段」且只在渲染过预览时
出现，一旦自动选中成品就回不去。现在只要 `pv.previewPath` 存在，胶囊行第一枚就是
「预览」，点它走 `selectPvOutSource(null)` 切回上次渲染的片段。
`pv-version` 的 `change` 监听随下拉一起删除，点击逻辑在生成胶囊时就地绑定。

### ④ 频谱两段式点击

两条轨道原先都在同一次 `pointerdown` 里「切轨 + 寻址」，于是想 A/B 对比换一条轨，
播放头顺手就被挪走了。改为点非激活轨时只切换并 `return`（`pvSelectTrack` 本身保持
播放状态与位置），第二次点击才走 seek / 拖拽饼 / 拖边缘。下轨的「音源不可用」早退分支不变。

### 第九轮验证

  - 三枚 tab 分别选中时，`border-left-color` 依次为
    选中=`rgb(168,59,88)`（accent-hi）、其后一枚=`rgba(0,0,0,0)`、其余=`rgb(214,213,216)`。
  - 播放条子元素只剩 `▶ / 时钟 / 胶囊组`，`pv-file-label` 不存在；

## 第十轮：每张卡片的无数据占位骨架（同日）

要求：没有数据时每个卡片都要有占位符，参照声场钻石——即使还没载入，也看得出这里大概会
显示什么东西。原先只有声场做到了：它空着也画出钻石外框、L/R/中标签和「— → —」读数；
其余三张卡是一句漂浮的「处理完成后显示」。

### ① 频响图：画真的坐标框，而不是贴一行字

`drawFreqSkeleton()` 画出 dB 网格（−10…−60）、共享的频率刻度与一条中性参考线，
再加一句「处理完成后显示「原始 / 处理后」两条曲线」。为了让数据到达的瞬间**不跳位**，
骨架与实图必须共用同一套几何：

- 内边距提成 `rpPlotPad(dpr)`（原先写死在 `drawSpectrumChart` 里）；
- 横轴刻度提成 `rpFreqTicks(ctx, X, dpr, h, faint)`，`tickPool` 升级为模块级
  `RP_FREQ_TICKS`；
- 骨架同样按 `rpZoom` 反解 X，所以空态下滚轮缩放看到的框也是当前视野。

实测：空态与有数据时画布内容的最左墨点都是 x=15、最底都是 y=258，两套几何一致。
参考线用**实线**——第五轮已要求频响区不用虚线，占位线也不破例。

### ② 响度与动态：五行固定量程的骨架本来就该画得出来

这一版把量程改成每行固定的常用总范围（第三轮），于是空态根本不需要额外设计：
去掉 `if (!pair) return` 的早退，读数取 `null`，刻度、单位、行标题照旧渲染。
唯一补的是读数槽——`<span class="rp-dyn-num empty">— → —</span>` 居中放在数字层里，
和声场卡同一读法。它不复用 `.both`：那个类的「后」一侧是方向色，会把「还没数据」
读成「衰减了」。空态行不登记重放钩子（没有圆点可插值，插了会写 NaN）。

### ③ 频谱变化与 KPI

`drawSpecBitmap` 在没有位图的分支里先调用 `drawFreqScale(...)`，再打印原因文案：
右侧的 14k/8k/…/100 标尺画出来，这一格是不用解释的频谱图。
KPI 卡无读数时方向位留空——`— —` 连印两个破折号看着像坏了，而不是「还没数据」。

### 验证中发现并修掉的

- **重放缺收尾**：`rpRunAnim` 先把所有钩子打到 `u=0`（起点），再靠 rAF 推回终态。
  窗口被遮挡时 rAF 可以整段不推进——在隐藏页面里实测，报告停在 `0.0 / 0.0 / 0.0 / 0.00`
  且曲线画布被 `clip-path` 全遮。补一个 `setTimeout(finish, ms + 250)` 兜底落终态，
  并在每次新动画开始时 `clearTimeout` 旧的看门狗，避免它去收尾已经被替换的动画。
  修复后同一隐藏页面在 t≈600ms 读到 `+1.3 / −1.0 / −0.8 / +1.94` 且裁剪已清空。

### 第十轮验证

- 真实浏览器空态（未选文件）：哑铃 5 行全部带 3–5 个量程刻度与 5 个「— → —」槽；
  频响画布有 3973 个非背景像素构成的框与网格；频谱画布右端 46px 标尺列有 8183 个
  标尺像素；KPI 四张各只有一个「—」。
- 载入成品后：哑铃 5 行 10 个圆点、空态槽归零，频响画布墨点范围与骨架完全一致（不跳位）。
- 全量 `python -m pytest -q`：622 passed, 1 skipped, 29 subtests passed。
