## 起因

用户反馈（附播放条截图，状态为「取消创建」即准备中）：

> 需要修改一下创建缓存时进度条的行为，在有进度之前，应该给一个准备动画（扫光效果），
> 进度条的变化应该有过渡效果。此外，修改播放器的进度条，使其占满高度，就是贯穿范围选择器区域。
> 还有进度条指针的三角形和竖线没有严格的对齐。

三条都能在代码里对上：

1. **有进度之前没有任何表态**：准备阶段唯一的视觉是 `.player-track::after` 那条 3px 状态线，
   `fraction` 还是 0 时它就是一条静止的主题色细线，与「已就绪」「出错」靠颜色区分，
   但**读不出「正在等第一批数据」**。而且进度是用 `--cache-progress` 直接改宽度，
   没有过渡——一次进度推送就是一次跳变。
2. **进度条只有底部 3px**：`--cache-progress` 只被底部状态线消费，范围选择带（20px）与轨道
   （44px）区域完全读不到「准备到哪了」。
3. **三角与竖线恒偏 0.5px**：1px 竖线占满 `[L, L+1]`，视觉中轴在 `L+0.5`。三角此前用
   `border: 4px solid transparent` 画——Blink 打底会把 border 宽度取整，**三角恒为偶数宽 8px**。
   偶数宽的盒子在整数像素边界上要么两边落在半像素（打底各自取整后整块平移 0.5px），
   要么中轴落在整数上（与 `L+0.5` 差 0.5px）——两种写法都不对齐。探针实测：旧写法
   `left:-4px` 与中途试过的 `left:50%; translateX(-50%)`，六个位置全部偏 **±0.5000px**，
   符号随小数部分翻转。

### 「占满高度」的口径说明

第 2 条中的「播放器的进度条」按**缓存进度指示本身**理解：用户同一句里把指针单独称作
「进度条指针」，而截图里可见的进度只有缓存那一条；且指针本就占满轨道高度（46px），
没有「占满」的余地。故本轮把**缓存进度**从 3px 底线改成整高底色，指针行为不动
（除第 3 条的对齐）。若原意是别的元素，此处可直接推翻。

> **后续修正（同日第二轮）**：用户明确指出这里理解反了——「占满高度」指的是**指针**
> （要向上贯穿到范围选择带顶），而整高进度底是多余的。整高底色与整宽扫光已收回，
> 详见 `cache_line_playhead_focus_20260922.md`。

## 行为与接口

### 缓存进度改整高（`ui/style.css` + `ui/app.js`）

- `--cache-progress` 从 `.player-track` 上提到 `.player`：整棵子树（含 `.player-timeline`
  的伪元素）都能继承同一个值，进度只有一处真源。
- `.player-timeline::before { inset: 0; width: var(--cache-progress); z-index: 1 }`——
  铺满时间轴的 72px（1px 上边框 + 4 内边距 + 20 范围带 + 3 间隙 + 44 轨道）。
  z 序刻意压在范围带的纱之上（否则被 38% 的纱吃掉浓度）、
  进度指针（z=2）与范围带底线（z=3）之下：指针永远踩在进度之上，底线仍是那条硬边状态线。
- 浓度：准备中 `color-mix(accent 16%)`，就绪后退一档到 8%（它是「已缓存」的底色，
  不该抢波形的视线）。
- `transition: width 260ms var(--ease), background-color 260ms var(--ease)`；
  `prefers-reduced-motion` 下 transition 关掉。
- 底部那 3px 状态线保留：它负责状态变色（中性/主题色渐变/主题色/红）与前缘硬边。

### 扫光准备动画（`ui/style.css` + `ui/app.js`）

- `cacheState()` 新增 `data-cache-sweep`：`status === 'preparing' && cacheFraction <= 0`。
  即「只有准备中、且一条进度都还没到」时才扫光；进度一来就撤。
  `fraction` 同时写进 `--cache-progress`，与底线、整高底色共用一个值。
- `.player[data-cache-sweep="true"] .player-timeline::after`：一条 100° 的斜向渐变带，
  `background-size: 260% 100%`，`background-position` 在 1.5s 内 95% → 5% 线性循环。
  百分比背景位置在放大图上左移内容，所以 95%→5% 就是**亮带自左向右走**；
  带心 x ≈ `W·(1.3 − 1.6P)`。`prefers-reduced-motion` 下 `display: none`。
- 「取消创建」路径（正在准备时再点按钮）改为 `cacheState('preparing','正在取消准备',cacheFraction)`：
  带着当前进度重写一次，扫光不会被误点亮（此时 `fraction > 0`），进度底也不会被打回 0。

### 指针三角（`ui/style.css`）

- 改为奇数宽盒子 + `clip-path`：

  ```css
  #player-playhead::before { content: ''; position: absolute; top: 0; left: -4px;
    width: 9px; height: 6px; background: var(--c-text);
    clip-path: polygon(50% 100%, 0 0, 100% 0); }
  ```

  盒子左沿与竖线左沿同为 `L-4` / `L`，**小数部分一致、打底取整同步**；
  顶点在 50% 处正好压在竖线中轴上。9px 是奇数，才可能同时做到「边沿对齐整数、
  中轴落在 1px 线的中心」。`clip-path` 的边是抗锯齿的，不受 border 宽度取整影响。

界面接口（id/属性）不变；纯 `ui/` 三个权威文件 + 测试断言 + 缓存版本号（`style.css?v=92`、`app.js?v=88`）。
