## 1. 结论

采用 Matchering 作为用户参考匹配候选生成器，由应用统一负责最终声场、响度、动态预算和输出验证。先完成无风格独立终段，再完成用户参考闭环，随后移除这两条路径及发行运行时对 Soren 的依赖。不要一次重写全部 DSP。

用户目前没有可随应用分发的参考音频，明确暂缓预置参考与风格系统。首版切换不再等待风格素材；多参考统计 profile 也不在本阶段范围内。

- 无风格：不调用 Matchering，不加载参考、Soren 模型或流派 profile；仍执行用户启用的修复、声场及统一最终母带。
- 用户参考：只使用用户选择的文件生成候选，再执行保护层与同一最终母带；参考不决定用户的目标响度。
- 无风格不等于母带旁路。母带旁路继续保持独立语义，输出报告如实说明未执行最终母带保护。
- 新版 UI 暂不提供预置风格；旧设置恢复时将预置风格迁移到无风格并提示。CLI 显式请求暂不支持的旧风格时清晰报错，不静默执行旧引擎。

第一版继续使用 44.1 kHz 内部采样率与 FLOAT WAV 中间文件；支持多种输入采样率不等于首版支持多种内部处理采样率。UI 暂不增加旋钮，不改变现有低频/瞬态等控件语义。

当前工作区已有多项未提交修改，特别是后端、缓存、报告与 DSP 阶段组合修复。后续实施以工作区现状为基线，不覆盖或回滚这些修改。

## 3. Matchering 接口核验

直接读取官方仓库当前 master 的 `core.py`、`results.py`、`defaults.py`、`stages.py`、`requirements.txt`、`setup.py`。其声明版本为 2.0.6，实施时需固定发布版本及源码身份，不能跟随 master 漂移。

- `process(target, reference, results, config)` 接收文件路径。
- `Result(path, "FLOAT", use_limiter=False, normalize=False)` 可以输出未限幅、未做输出归一化的候选文件。
- **这不关闭上游电平匹配或 M/S 独立 FIR 匹配**，`stages.py` 仍先匹配电平、频谱并进行 RMS 校正。
- `Config` 没有直接的 reference strength 或关闭 M/S 匹配参数。`rms_correction_steps=0` 只关闭后续迭代，不取消初始电平匹配。
- 默认内部采样率 44100；其他内部采样率上游明确注明未充分测试。
- 默认长度上限 15 分钟；主流程要求源与参考均长于 fft_size。需要实测长曲、短片段和静音处理策略，防止时长意外变化。
- 依赖 numpy/scipy/soundfile/resampy/statsmodels。移除 Soren 不意味着 statsmodels/numba 等必然可以删除，需检查完整依赖图。
- 源文件许可为 GPL-3.0-or-later；项目 README 当前声明尚无项目级开源许可证。正式发行前需确定组合发行与源码提供方式。

更新：已在本机独立验证环境运行 Matchering 2.0.6，确认 FLOAT/关闭 limiter 接口、两段真实音乐长度保持及十组采样率组合；发现合成信号 +1 sample 时延。完整曲目内存、干净发行环境与听感仍待验证，详见本批报告。

## 4. 建议处理链与关键边界

解码/重采样 → Lew/分轨 → 低频、鼓、人声、降噪与去拥挤修复 → 用户参考匹配候选（无风格跳过） → 匹配保护 → 最终混音声场 → 动态与响度 → True Peak → 最终量化与写盘 → 文件回读报告。

### 声场不能仅移动现有阶段

`soundstage_reshape` 目前组合去拥挤、降噪、分轨宽度 delta 和峰值缩放。将整个脚本移到 Matchering 后会把旧分轨差值加到已被不同 M/S FIR 与增益改变的混音上；单一 stem_scale 无法修复这种频率相关变换。

建议把降噪、去拥挤留在分轨修复阶段，将最终宽度控制拆为面向当前混音的处理。原始分轨可提供检测信息，但不直接作为匹配后混音的音频增量。保留原曲低频 Side，仅限制新增 Side。

声场保护要分别比较：匹配前/后、宽度处理前/后、最终文件/处理基线。只比较 Matchering 输出与随后加宽结果，会遗漏 Matchering 已经造成的收窄。近单声道不通过无限放大 Side 制造宽度；不安全时保守回退。

### 强度不是简单波形干湿比

现有风格强度是处理量。直接混合完整原声和 Matchering 输出可能重现旧版相位抵消问题。第一批只做完整候选接受/拒绝与基线回退，不宣称已支持连续匹配强度。

第二批验证有限的内部适配：限制参考驱动的 FIR 修正、电平和 M/S 差异，强度在处理参数域生效。若公共 API 不足，再决定是否维护小范围、固定版本的上游补丁；不提前设计完整 fork 框架。

对 EQ/低频/人声意图也要设置匹配预算，不能只保护宽度。现有 upstream_delta 机制需要明确替代方案后才能删除。

### 最终输出独立于 Soren

新建 `mastering/`，初步职责为 adapter、guard、finalizer；测量与报告优先复用 `audio_metrics.py`。暂不创建风格 profiles 系统，也不再新建重复测量系统。

迁移共同终段时先审计来源：不能把 Soren 文件改名就视为解除依赖。可复用的自研逻辑提取为独立模块；来源/使用权不明的部分按明确算法与现有测试合同重新实现。

保持参考音色与用户响度选择分离。现有响度目标依赖流派 profile，需要改为应用自有的固定档位映射；首版拟以当前默认无风格路径的实测目标为兼容基线，在批次 A 给出明确数值与来源，不保留运行时 profile 读取。峰值上限先维持当前合同；动态预算不足时允许未达目标并报告原因。最终量化只做一次。

## 5. 分阶段交付（按用户确认范围收敛）

| 批次 | 范围 | 完成条件 |
|---|---|---|
| A：可行性与基线 | 固定 Matchering 版本并独立验证；记录无风格/用户参考基线；确定无流派依赖的响度映射；审计 finalizer 来源 | 明确采样率、时延、长度、资源占用及 API 缺口，不改默认处理 |
| B：无风格独立闭环 | 引入独立母带入口与 finalizer，接入报告、取消、缓存和回读 | 无参考文件且没有 Soren 资源时，仍能完成无风格处理；动态与 TP 合同通过 |
| C：用户参考与声场 | 拆分声场职责；接入 Matchering、匹配预算、强度与候选回退；两种模式共用终段 | 回退到应用无风格路径；参考不覆盖用户响度；等响 A/B 与完整输出验证通过 |
| D：默认切换与依赖移除 | 迁移旧设置，暂缓预置风格入口；移除 SB_SOREN、模型/profile 装配及运行调用 | 干净环境和 CPU/GPU 安装包均能完成两种模式，旧缓存不会混用 |
| E：DSP 逐项优化 | 饱和补偿、局部瞬态、降噪、Lew 对齐及中途 headroom | 每项单独测试、等响试听与验收，不与引擎替换混为一次大改 |

过渡期只允许开发/验证中的旧引擎对照，不把自动回退偷偷导向 Soren。两种模式通过验收即可切换，不等待预置风格。

用户以后收集到可分发的参考素材，再单独启动预置风格计划。不要从旧加密 profile 推导或复制新风格资产，也不把单纯 EQ 预设伪装成 Matchering 风格匹配。用户参考文件不复制进应用资源或安装包。
