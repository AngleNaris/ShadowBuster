# Lew 快速档显存修正与在线文档核查

## 修改
studio_backend.QUALITY_CHUNKS 的快速档从20秒块/1秒重叠改为6秒块/0.5秒重叠。标准15/2和精细10/3保持原样。FP32、batch=1、模型权重均不变；UI不改。6秒是上游长音频示例使用的长度，0.5秒重叠是本项目快速档选择，不是上游推荐值。未实现自动显存适配，标准/精细档仍可能对8GB显存造成压力。

## 测量
本机 RTX5060 Ti 16GB，现有GPU运行时，同一原曲开头30秒，转换到44.1kHz，每档独立子进程。计时为模型加载完成后的首次推理（包含首次算子初始化、CPU/GPU传输和分块拼接），不是多轮稳态平均，也不是纯kernel时间。显存是PyTorch allocator峰值，不含全部驱动与其他进程显存。

|快速档|推理秒数|peak allocated MiB|peak reserved MiB|
|---|---:|---:|---:|
|旧20/1|10.521|12342.37|13854|
|新6/0.5|6.697|3806.16|4280|

本次推理时间下降约36.3%，峰值allocated下降约69.2%。输出均为有限值，形状完全相同（1×2×1323000）；分块变化会改变音频上下文与接缝，不声称逐样本一致或已经人工确认音质等价。试听WAV及原始统计位于 lew_fast_20260906_204741/。

旧快速档在本机的实际峰值分配约12.1GiB，明显超出8GB容量。这为用户8GB RTX5060上满显存慢提供了强支持，但未测量对方机器，不能断言其实际共享显存回退或具体加速倍数。

## 在线核查
- https://github.com/JusperLee/Apollo ：长音频示例 --chunk-seconds=6，overlap=1，context padding=1，batch=2。说明batch默认1用于最小加速器内存，增大batch会增加内存并可能提升速度。没有给出Lew Universal最低显存数字。当前本地Lew包装器没有该示例的context-padding参数，不能直接视为同一推理配置。
- https://huggingface.co/JusperLee/Apollo ：模型卡未说明最低显存、量化版或混合精度；提供1秒信号的GPU推理时间描述，但不构成Lew完整歌曲显存保证。
- PyTorch CUDA notes与empty_cache在线文档尝试超时，未把未成功抓取的页面作为本次联网确认的证据。
